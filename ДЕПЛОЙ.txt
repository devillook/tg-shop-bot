Перенос бота на Fly.io (бесплатный долю, 24/7) через GitHub
=============================================================

ГЛАВНОЕ: бот хранит всё важное в shop.db и sessions/ (вход в @jonnkq и во все проданные
аккаунты). Эти файлы НИКОГДА не попадают в GitHub (см. .gitignore) — на хостинге их заменяет
постоянный диск (volume), который переживает перезапуски и обновления.

1) Залить код на GitHub
------------------------
- Создай приватный репозиторий на github.com (приватный — обязательно, в коде админ-команды).
- В папке проекта:
    git init
    git add .
    git commit -m "init"
    git branch -M main
    git remote add origin https://github.com/ТВОЙ_ЛОГИН/ИМЯ_РЕПО.git
    git push -u origin main
  .env, shop.db и sessions/ не попадут в репозиторий — это нормально, так и должно быть.

2) Завести аккаунт на Fly.io и подключить CLI
----------------------------------------------
- Зарегистрируйся на fly.io (можно через GitHub). Потребуется привязать карту даже для
  бесплатного лимита — с неё ничего не спишут, пока не выйдешь за лимит.
- Установи flyctl: https://fly.io/docs/flyctl/install/ (для Windows — через PowerShell команду
  с той же страницы).
- В терминале: flyctl auth login

3) Создать приложение и постоянный диск
-----------------------------------------
В папке проекта:
    fly launch --no-deploy
  — придумай имя приложения (впиши такое же в fly.toml вместо "ИМЯ-ТВОЕГО-ПРИЛОЖЕНИЯ"),
    регион можно оставить fra (Франкфурт). На вопросы про базу данных отвечай "нет" — своя
    SQLite нам хватает.

    fly volumes create data --region fra --size 1
  — создаёт постоянный диск на 1 ГБ (хватает с большим запасом), он уже прописан в fly.toml
    как /data. Регион должен совпадать с primary_region в fly.toml.

4) Передать секреты (токен, хеши и т.д.) — НЕ через .env, а так:
------------------------------------------------------------------
    fly secrets set BOT_TOKEN=... ADMIN_IDS=... ADMIN_USERNAME=jonnkq API_ID=... API_HASH=... ^
      SUB_CHANNEL=codcrytg BETA_MODE=0
  (в PowerShell перенос строки — знак ^ ; в bash/Linux — обратный слэш \)
  Впиши все переменные, какие использовал(а) в своём .env, кроме DATA_DIR — он уже прописан
  в fly.toml и доставлять его secrets не нужно.

5) Первый деплой
------------------
    fly deploy
  Подожди, пока сборка завершится. Дальше бот уже крутится 24/7 на Fly.

6) Войти в свой аккаунт @jonnkq на сервере (один раз)
--------------------------------------------------------
Session-файл создаётся только через интерактивный ввод кода, поэтому один раз делаем это
прямо на сервере:
    fly ssh console
    cd /app
    python login_owner.py
  Введи номер и код как обычно. После этого выйди (exit) — сессия останется на диске /data
  и переживёт любые будущие обновления.

Все остальные аккаунты на продажу добавляй уже ОБЫЧНЫМ способом — через "🛠 Админ-панель"
в самом боте (как и раньше), это и есть основной сценарий теперь.

7) Автодеплой при пуше в GitHub
----------------------------------
В файле .github/workflows/fly-deploy.yml уже всё готово. Нужно только:
  - Получить токен: fly tokens create deploy -x 999999h
  - На GitHub: репозиторий → Settings → Secrets and variables → Actions → New repository
    secret → имя FLY_API_TOKEN, значение — токен из предыдущего шага.
Теперь каждый "git push" в ветку main сам обновит бота на Fly за 1-2 минуты. Данные (база,
сессии) при этом не трогаются — они на отдельном постоянном диске.

Проверка, что всё живо
-------------------------
    fly logs          — смотреть лог бота в реальном времени (то же самое, что видно в консоли
                         локально: [ЗАКАЗ], [АВТОКОД], [ПОДАРОК] и т.д.)
    fly status         — работает ли машина
    fly ssh console    — зайти "внутрь" сервера, если нужно что-то проверить руками

О бесплатности
-----------------
У Fly.io нет "вечно бесплатного" тарифа без карты, но на таком маленьком боте (одна лёгкая
машина + 1 ГБ диска) расход почти всегда укладывается в бесплатный ежемесячный лимит Hobby-
плана. Если нужен тариф вообще без привязки карты — это либо VPS (например, вечно бесплатный
уровень Oracle Cloud, сложнее в настройке, тоже можно через git clone), либо Render/Railway, но
там либо нет бесплатного постоянного диска, либо бесплатный тариф "засыпает" без постоянного
HTTP-трафика — а наш бот не веб-сервер, и его "разбудить" будет нечем. Для магазина, где
важно не потерять базу и сессии аккаунтов, Fly.io с постоянным диском — самый надёжный
бесплатный/дешёвый вариант из перечисленных.
